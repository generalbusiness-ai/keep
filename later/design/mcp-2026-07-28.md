# MCP 2026-07-28 implementation design

Status: implemented for `v0.163.0`; hosted integration follows public publication.

## Decision

Keep one semantic MCP contract in `keep/mcp_surface.py`. Local stdio and hosted
Streamable HTTP supply small service adapters for flow execution, note reads,
and help text. They must not register their own copies of tools, schemas,
prompts, resources, annotations, or error behavior.

The server is built on the stable Python MCP SDK v2 API. It advertises the
final 2026-07-28 protocol while retaining the SDK's legacy 2025-11-25 path for
existing clients. This compatibility belongs at the protocol boundary; core
flow and store code remain unaware of protocol eras.

## Contract

- Tools: `keep_flow`, `keep_prompt`, and `keep_help`.
- Native prompts: prompt notes explicitly tagged for MCP exposure.
- Resources: `keep://now` and the `keep://{id}` template.
- `keep_flow` is truthfully annotated as potentially mutating, destructive,
  and non-idempotent. Prompt/help tools are read-only and idempotent.
- Flow and prompt tools have typed output schemas and return
  `structuredContent` alongside readable text.
- Failed flow calls become MCP tool errors. Missing resources and prompts use
  protocol errors, rather than successful strings containing an error prefix.
- Dynamic catalogs use private, zero-duration cache hints because notes and
  prompt metadata can change between requests.
- The server does not advertise resource subscriptions or list-change
  notifications. Keep cannot observe every change made through the daemon or
  another client, so advertising those capabilities would promise events it
  cannot deliver reliably.

`FlowParams` explicitly documents common keys but allows extensions for custom
state docs. `source` is canonical for move operations; `source_id` is accepted
only as an input compatibility alias and normalized before it reaches a flow.

## Runtime boundaries

The local adapter remains a thin client of the daemon. Synchronous REST calls
run in cancellable worker threads so they do not block MCP dispatch. The daemon
continues to own durable/background work and store serialization.

A host mounting the Streamable HTTP ASGI application must run the MCP session
manager from its top-level lifespan. Mounted Starlette applications do not
receive lifespan automatically. Streaming authentication middleware must be a
pure ASGI wrapper so response streams and cancellation are not buffered by
`BaseHTTPMiddleware`.

The SDK's HTTP parser rejects legal leading/trailing optional whitespace in
final-protocol routing headers. A narrow ASGI boundary normalizer strips only
space and horizontal-tab padding from MCP routing/custom header values while
preserving header order and duplicates. It does not rewrite ordinary HTTP
headers or relax header-name/value validation.

Gateways must forward `MCP-Protocol-Version`, `Mcp-Method`, and `Mcp-Name`, and
allow them in CORS preflight. They must not infer tool mutability from HTTP POST:
all MCP requests use POST, so the authenticated semantic adapter is the policy
authority.

## Authorization profile

OAuth is optional in MCP 2026-07-28. A deployment using a pre-provisioned API
key may keep that credential out-of-band, but must document that it does not
implement the MCP OAuth profile. It must not publish Protected Resource
Metadata pointing to a nonexistent authorization server.

If OAuth is added later, introduce it as a separate resource-server adapter:

1. Select or operate a genuine OAuth 2.1 authorization server.
2. Validate issuer, audience/resource, expiry, and scopes at the gateway.
3. Publish RFC 9728 Protected Resource Metadata with that issuer.
4. Publish RFC 8414 or OIDC discovery and support one of the specified client
   registration paths.
5. Map scopes to read/write/admin permissions and preserve API keys as a
   separate compatibility credential until callers migrate.

Do not make the MCP semantic surface or flow engine aware of OAuth tokens.

## Verification and release order

Contract tests cover both protocol eras, structured results, truthful
annotations, compatibility aliases, protocol errors, resources, and native
prompts. Hosted tests must enter the parent lifespan and make an authenticated
wire request; unit-testing only the 401 path cannot detect a stopped session
manager. Gateway tests cover preflight, header forwarding, and read-only keys.

Because the hosted adapter imports `keep.mcp_surface`, release the public
`keep-skill` feature version first. Then raise the hosted dependency floor,
regenerate its lock, run integration/conformance tests against the published
artifact, and deploy. Never temporarily duplicate the shared surface in the
hosted repository to bypass this ordering.
